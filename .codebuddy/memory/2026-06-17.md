## stegdetect-py: Outguess 检测优化 (mmm.jpg 漏检修复)

### 根因
- `prepare_outguess` 排除了 ±1 系数（8111/18426=44%），但 Outguess 修改所有非零AC的LSB，信号大量丢失
- `unify_outguess` 严格模式丢弃全部125个pair（`fbar >= f/3` 条件过于激进）
- chi2_test 对 Outguess 效果差（Outguess 设计上保留卡方统计量）
- 缺少扩展卡方 (k=2) 策略（原始 stegdetect C 代码的核心方法）

### 修复
1. **`jpeg_dct.py`**：新增 `prepare_outguess_detect` → 包含所有非零AC（含 ±1），bits 从 11102 提升到 19213
2. **`histogram.py`**：新增 `unify_outguess_k2` → 4-bin 分组扩展卡方配对，检测 Outguess 无法保持的 k=2 级对称性
3. **`detectors.py`**：
   - 新增 `_outguess_extended_chi2` 策略 → 多窗口滑动 k=2 卡方分析（权重 30%）
   - `asymmetry` 阈值 0.3→0.15；`rs` 最低 bits 100→50
   - `detect_outguess` 用 `prepare_outguess_detect`、移除无效 block_variance、调整权重
   - 权重分配：ext_chi2 0.3, asym 0.2, lsb_chi2 0.15, rs 0.15, chi2 0.1, rand 0.1

### 验证
- `uv run stegdetect.py -t o -v mmm.jpg` → `"outguess" (possibly, lsb_chi2=0.063, asym=0.206, rs=0.132, ext_chi2=0.101)`
- 组合分数 ~0.10，通过阈值 0.1

## Steghide 检测支持 (保守实现)

### 技术背景
Steghide 使用图论匹配算法：在 DCT 系数中寻找差值恰好为1的"可交换对"，通过交换值来嵌入数据，**完全保持不变一阶直方图**。这使其检测比 JSteg/Outguess/F5 难得多——简单卡方测试完全无效。

### 实现内容
1. **`jpeg_dct.py`**：新增 `prepare_steghide(info)` → 返回 `(data, bits, block_starts)`，包含所有非零AC及块边界
2. **`histogram.py`**：新增 `unify_steghide(hist)` → 相邻值配对（如 (1,2), (3,4), (-3,-2)），跳过涉及-1/0/1的bin；新增 `unify_steghide_block_level`
3. **`detectors.py`**：
   - 新增 `FLAG_STEGHIDE = 0x40`，`FLAG_ALL` 包含它
   - 4个检测策略（均为保守阈值，防止误报）：
     - `corr`：块间相邻值相关性（连续块 vs 远距块对比）
     - `gld`：全局 vs 局部卡方差异（全局低+局部高=steghide特征）
     - `chi2`：多窗口滑动卡方扫描
     - `var`：块间正负值比例和偶数LSB比例的方差
   - 共识机制：<2策略=0.25x，2策略=0.5x，>=3策略正常
4. **`cli.py`**：支持 `-t h`（Steghide），`-t jopfiFh` 全部检测
5. **`__init__.py`**：文档更新

### 设计原则
保守优先：没有实际 steghide 嵌入样本校准，阈值设置为宁可漏检（false negative）也不误报（false positive）。

### 验证
- `uv run stegdetect.py -t h -v mmm.jpg 1.jpg guess.jpg` → 0/3 检测（正确，三张均非 steghide）
- `uv run stegdetect.py -t o -v mmm.jpg` → Outguess 检测仍正常
- `-V` 正常输出 `stegdetect (Python rewrite) 1.0.0`
- 无 lint 错误

## Steghide 检测优化 (v2 - 灵敏度提升)

### 根因
初版检测器过于保守：严格共识机制(需≥2策略，单策略打0.25折)、`gld` 要求 `global_chi2<0.1`(对混合嵌入图像不成立)、阈值太高。导致1.jpg(F5+steghide)完全无法检测。

### 修复
重写为3策略设计，移除共识惩罚：

1. **`_steghide_window_chi2_stats`** (新)：在2%/5%/10%三种窗口尺度下计算滑动chi2，返回(mean, spread, max)。1.jpg: mean=0.342, spread=0.694
2. **`_steghide_local_chunk_chi2`** (新)：固定大小分块chi2，返回(local_avg, global)。1.jpg: local=0.636, global=0.272
3. **`detect_steghide`** (重写)：
   - score_mean: 窗口均值>0.12触发（mmm.jpg=0.06排除了）
   - score_spread: 窗口跨度>0.30触发（mmm.jpg=0.27排除了）
   - score_local: 局部chi2>0.10触发
   - gap_bonus: global_chi2<0.05时+0.15（纯steghide强烈信号）；local>global*1.5时+0.05（混合嵌入弱信号）
   - 权重 0.35/0.25/0.40，无共识惩罚
   - bits阈值 500→100

### 验证
- `1.jpg`: **detected** (probably, win_mean=0.342, spread=0.694, local=0.636, gap_bonus) confidence≈0.89
- `guess.jpg` (F5): **detected** (probably, win_mean=0.303, spread=0.645, local=0.641) — F5嵌入创建了类似局部异常
- `mmm.jpg` (outguess): **not detected** — 正确，全局局部都平衡
- 综合检测 `-v mmm.jpg 1.jpg guess.jpg`：所有类型正常

### 已知局限
- guess.jpg 也被标记为 steghide，因为它本身是 F5 嵌入图（全检测确认），F5 的 DCT 修改创建了类似 steghide 的局部 chi2 异常
- 纯 steghide（无其他工具嵌入）会有更强的 gap_bonus 信号 (global≈0)

## F5 检测误报修复

### 根因
旧代码用 Q=90-98 重压缩一个 Q=75 的原始 JPEG，量化表不匹配导致 DCT 系数变化巨大（清洁 mmm.jpg 的 beta 飙到 15.77），完全淹没 F5 嵌入信号，造成严重误报。

### 修复
重写 `detect_f5_slow()`（f5.py）：
1. **`_estimate_jpeg_quality()`**（新）：从量化表反推 JPEG 质量，匹配 IJG 标准表。测试图全部正确识别为 Q=75
2. **用预估质量重压缩**：不再尝试 Q=90-98，而是用预估的 Q=75 重压缩（无损再压缩无信息损失），消除量化不匹配假象
3. **评分校准**：三位置 beta 评分 + 共识机制（需≥2 位置有信号），beta(1,2) 阈值 0.20（清洁图为 0.00）
4. 输出质量信息：`Q=75, beta(1,2)=0.000, ...`

### 验证
- `_gen_f5_test.py`：F5 嵌入器，从 mmm.jpg 生成 15%/35%/60% 嵌入率测试图
- 验证结果（beta 随嵌入率单调递增）：
  - mmm.jpg（清洁）：未检测 ✓（零误报）
  - f5_light.jpg（15%）：beta=1.815, probably
  - f5_medium.jpg（35%）：beta=2.037, probably
  - f5_heavy.jpg（60%）：beta=2.650, definitely
- 1.jpg（实际为 ~55% F5）：beta=2.502, probably
- guess.jpg（轻微 F5）：beta=0.529, possibly
- 清洁图片零误报，各嵌入率全部检出
